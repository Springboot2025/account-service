# PayWay Integration

Lawyer subscriptions (Individual / Firm, monthly / yearly) paid by card through **Westpac PayWay**.

Related: [Frontend guide](FRONTEND_GUIDE.md) · [Code walkthrough](CODE_WALKTHROUGH.md) · Postman: `postman/PayWay_Frontend.postman_collection.json`, `postman/PayWay_Backend.postman_collection.json`

All example responses below were captured from a real run against the PayWay sandbox, except Cancel (4.5), which shows the response shape.

---

## 1. Flow

### First payment

```
Browser                         account-service                                  PayWay
───────                         ───────────────                                  ──────
1. Lawyer logs in, picks a plan (Monthly / Annually) and clicks Select Plan
2. Card form (payway.js, publishable key) ───────────────────────────────────────▶ POST /single-use-tokens
   ◀───────────────────────────────────────────────────────────── singleUseTokenId
3. POST /api/payway/payments ──▶ a. validate plan + amounts against the DB
   { planId, planDuration,         b. invoice (DUE) + payment row (PENDING) saved
     amount, gstAmount,            c. PUT  /customers/{LAW-12 | FIRM-5} ──────────▶ customer created, card saved
     totalAmount,                  d. POST /transactions (customerNumber) ────────▶ charge the saved card
     singleUseTokenId }               ◀────────────────────────────────── approved / declined
                                   e. payment row updated with PayWay's response
                                      approved → invoice PAID, subscription ACTIVE, renews_at set
   ◀── 200 approved / 402 declined
```

Every call to PayWay (c, d) is also written to `payway_api_logs` with sensitive values masked.

### Renewals (automatic)

```
Daily 02:00 Melbourne ─▶ subscriptions with status ACTIVE and renews_at reached
                          a. RENEWAL invoice for the next period (same amounts as the last paid invoice)
                          b. POST /transactions (customerNumber) ───────────────▶ charge the saved card
                          c. approved → invoice PAID, renews_at moves to the end of the new period
                             declined → invoice OVERDUE, retried next day; after 3 declines the subscription goes INACTIVE
```

### Billing history

```
GET /api/payway/invoices ─▶ the payer's invoices (PAID / OVERDUE / DUE renewals), newest first
```

### Cancel

```
POST /api/payway/subscription/cancel ─▶ subscription status 2 (cancelled): the renewal job stops charging
                                        access continues until renews_at, no refund
                                        open renewal invoices (DUE / OVERDUE) → VOID
                                        then PATCH /customers/{n}/payment-setup stopped=true ──▶ PayWay rejects any further charge
                                        (second lock; the saved card stays in the vault, re-subscribing clears the flag)
```

## 2. Concepts

| Concept | Value | Notes |
|---|---|---|
| Payer | The logged-in lawyer (from the JWT) | Individual lawyer, or the firm admin (`isCompany = true`) paying for the firm. Lawyers who joined a firm get `403`. |
| Customer number | `LAW-<accounts.id>` / `FIRM-<companies.id>` | One PayWay customer per payer; holds the saved card. Max 20 chars (PayWay limit). |
| Order number | `BJ<yyMMdd>-<seq>`, e.g. `BJ261004-00000002` | One per payment attempt, generated by the DB. Shown in the PayWay portal. |
| Invoice number | `INV<yyMMdd>-<seq>`, e.g. `INV261004-00000001` | One per billing period, generated by the DB. |
| Single-use token | From PayWay (`payway.js`) | Card details never reach our server. Usable once, expires after 10 minutes. |
| Amounts | `amount` (excl. GST) + `gstAmount` = `totalAmount` | `amount` must equal the plan price in `subscriptions`; `totalAmount` is charged. |

**Status values**

| Payment (`payway_transactions.status`) | Invoice (`subscription_invoices.status`) | Subscription (`user_subscriptions.status`) |
|---|---|---|
| `PENDING` – PayWay call in progress | `DUE` – waiting for payment | `0` – inactive |
| `APPROVED` | `PAID` | `1` – active |
| `DECLINED` – declined by the bank | `OVERDUE` – renewal declined, retrying | `2` – cancelled |
| `ERROR` – rejected by PayWay / unreachable | `VOID` – replaced (user switched plan) | |

## 3. Setup

| Env var | Production (Secret Manager) | Local `.env` |
|---|---|---|
| `PAYWAY_SECRET_KEY` | `payway-secret-key` | sandbox secret key (`T…_SEC_…`) |
| `PAYWAY_PUBLISHABLE_KEY` | `payway-publishable-key` | sandbox publishable key (`T…_PUB_…`) |
| `PAYWAY_MERCHANT_ID` | `payway-merchant-id` | `TEST` |
| `PAYWAY_RENEWAL_AUTO_ENABLED` | `payway-renewal-auto-enabled` | `false` (`true` to run renewals) |
| `PAYWAY_RENEWAL_CRON` | – (default) | optional, default `0 0 2 * * *` (Melbourne) |
| `PAYWAY_BASE_URL` | – (default) | optional, default `https://api.payway.com.au/rest/v1` |

- Keys come from the PayWay portal: **Settings → REST API Keys**. Sandbox and live use the same URL; the keys decide which facility is used.
- If the keys or merchant id are missing the app still starts; payment calls return `503`.
- Saving cards needs PayWay's **Recurring Billing and Customer Vault** module on the facility.
- Database: migrations `V76__create_payway_transactions.sql` (tables `subscription_invoices`, `payway_transactions`, `payway_api_logs`; column `user_subscriptions.payway_customer_number`) and `V77__user_subscription_cancellation.sql` (`user_subscriptions.cancelled_at`, `cancel_reason`).

### 4.3 Make a payment

`POST /api/payway/payments` — Lawyer role.

| Field | Type | Rules |
|---|---|---|
| `planId` | number | Plan id from the `subscriptions` table |
| `planDuration` | string | `monthly` or `yearly` |
| `amount` | number | Must equal `monthly_price` / `annual_price` of the plan |
| `gstAmount` | number | ≥ 0 |
| `totalAmount` | number | Must equal `amount + gstAmount`; this is charged |
| `singleUseTokenId` | string | From 4.2 |

```bash
curl -X POST $BASE/api/payway/payments \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \

        "planDuration": "monthly",
```

**Errors**

| HTTP | When | Example `message` |
|---|---|---|
| 400 | Missing / invalid fields | `"Validation failed"`, `data: { "singleUseTokenId": "must not be blank", "totalAmount": "must not be null" }` |
| 400 | `amount` ≠ plan price | `"amount 5 does not match the monthly plan price 50.00"` |
| 400 | `totalAmount` ≠ `amount + gstAmount` | `"totalAmount must equal amount + gstAmount"` |
| 403 | Lawyer belongs to a firm (not the admin) | `"Your firm's subscription is managed by the firm admin"` |
| 409 | Already has an active subscription | `"You already have an active subscription"` |
| 409 | Another payment by the same payer is in progress (double click) | `"A payment is already in progress, please wait a moment"` |
| 422 | PayWay rejected the token / card | `"Invalid single use token.  Tokens expire after 10 minutes, may only be used once and must be used by the PayWay facility under which they were created."` |
| 502 | PayWay unreachable, or the payment still pending at PayWay after ~15 s | `"Payment gateway is unavailable, please try again shortly"` |
| 503 | PayWay keys / merchant id not configured | `"Payments are not available: PayWay is not configured"` |

### 4.5 Cancel subscription

`POST /api/payway/subscription/cancel` — Lawyer role. Body optional.

| Field | Type | Rules |
|---|---|---|
| `reason` | string | Optional, max 1000 chars ("Tell us why you're leaving") |

```bash
curl -X POST $BASE/api/payway/subscription/cancel \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{ "reason": "Too expensive" }'
```

**200 — cancelled** (shape; values from the test lawyer above)

```json
{
  "code": 200, "status": "success", "message": "Subscription cancelled",
  "data": {
    "subscriptionUuid": "f3547556-e18c-459f-810e-b72ffd5edc54",
    "status": 2,
    "planId": 1,
    "planName": "Subscription for Individual Lawyers",
    "planDuration": "monthly",
    "startDate": "2026-10-03T15:47:22",
    "accessUntil": "2026-11-04T00:00:00",
    "cancelledAt": "2026-10-04T08:30:00",
    "cancelReason": "Too expensive",
    "voidedInvoices": 0,
    "paywayPaymentsStopped": true
  }
}
```

`accessUntil` is the date to show as "Access continues until". `voidedInvoices` > 0 when a renewal was overdue at the time of cancelling. `paywayPaymentsStopped` is `false` only if the PayWay stop call failed — the cancel itself still succeeded (renewals are stopped by our DB status); the failure is in the logs and `payway_api_logs`.

**Errors**

| HTTP | When | `message` |
|---|---|---|
| 403 | Firm member | `"Your firm's subscription is managed by the firm admin"` |
| 404 | Never subscribed | `"No subscription found"` |
| 409 | Not active (already cancelled, or inactive) | `"No active subscription to cancel"` |

To subscribe again later the lawyer goes through **Make a payment**: the new period starts on the day of payment, and the cancellation fields are cleared.

## 5. PayWay calls made by the server

All with the **secret key** as the HTTP Basic username (blank password), `application/x-www-form-urlencoded` body.

| Step | PayWay call | Fields sent |
|---|---|---|
| Save customer + card | `PUT /customers/{customerNumber}` | `singleUseTokenId`, `merchantId`, `customerName`, `emailAddress`, `sendEmailReceipts=false` |
| Charge | `POST /transactions` + header `Idempotency-Key` | `transactionType=payment`, `customerNumber`, `principalAmount`, `currency=aud`, `orderNumber` |
| Slow network (`202 pending`) | `GET /transactions/{transactionId}` | every 3 s, up to 5 times |
| Cancel (stop all payments) | `PATCH /customers/{customerNumber}/payment-setup` | `stopped=true`. PayWay then rejects charges with "All remaining payments for this customer have been stopped". Saving a card (`PUT /customers/{n}`) resets it to `false`. |

- A timeout, `429` or `503` is retried once with the same `Idempotency-Key`, so PayWay can't charge twice.
- PayWay `422` (bad token / card) → our `422` with PayWay's message. PayWay `401/403` → our `502` ("not configured correctly").

**Useful sandbox/debug calls** (secret key) — also in the backend Postman collection:

```bash
curl https://api.payway.com.au/rest/v1/customers/LAW-4 -u "$PAYWAY_SECRET_KEY:"
curl "https://api.payway.com.au/rest/v1/transactions/search-customer?customerNumber=LAW-4" -u "$PAYWAY_SECRET_KEY:"
curl "https://api.payway.com.au/rest/v1/transactions/search-order?orderNumber=BJ261004-00000002" -u "$PAYWAY_SECRET_KEY:"
```

## 6. Database

| Table | One row per | Key columns |
|---|---|---|
| `subscription_invoices` | billing period | `invoice_number`, `user_uuid`, `user_subscription_uuid`, `invoice_type` (INITIAL / RENEWAL), `period_start`, `period_end`, `amount`, `gst_amount`, `total_amount`, `status`, `paid_at`, `failed_attempts` |
| `payway_transactions` | payment attempt | `order_number`, `invoice_uuid`, `user_uuid`, `customer_number`, `idempotency_key`, amounts, `status`, PayWay response (`payway_transaction_id`, `receipt_number`, `response_code`, `response_text`, `card_scheme`, `masked_card_number`, `settlement_date`, …), `error_message` |
| `payway_api_logs` | HTTP call to PayWay (audit, append-only) | `payway_transaction_uuid`, `operation`, `http_method`, `endpoint`, `attempt`, `request_headers`, `request_body`, `response_status`, `response_body`, `error_message`, `duration_ms` |
| `user_subscriptions` (existing) | subscriber | new columns `payway_customer_number` (V76), `cancelled_at`, `cancel_reason` (V77); `status`, `plan_id`, `plan_duration`, `start_date`, `renews_at` set on approval |

**Audit masking** (`payway_api_logs`): the `Authorization` header (secret key), card numbers, CVN and bank account numbers are never stored; `singleUseTokenId` is stored as `****<last 4>`; card numbers PayWay returns already masked (`456471...004`) are kept.

```json
{
  "operation": "SAVE_CUSTOMER", "http_method": "PUT", "endpoint": "/customers/FIRM-1", "attempt": 1,
  "request_headers": { "Accept": "application/json", "Content-Type": "application/x-www-form-urlencoded" },
  "request_body": { "merchantId": "TEST", "customerName": "Test Firm Pty Ltd", "emailAddress": "firmadmin@test.local",
                    "singleUseTokenId": "****a63f", "sendEmailReceipts": "false" },
  "response_status": 422, "duration_ms": 352
}
```
